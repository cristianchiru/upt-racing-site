Getting Started

Prerequisites

Before you can run or edit the website you need the following tools installed on your computer:

Node.js
v18 or newer
node -v to check
Package Manager
npm (comes with Node) or pnpm
Code Editor
VS Code recommended
with Astro extension

Install Node.js from nodejs.org if you don't have it. You can verify with node -v in your terminal.

Clone & Install

  1. Clone the repository from GitHub to your computer.

  2. Open a terminal in the project folder.

  3. Install dependencies:

Terminal
npm install

Run the Development Server

Terminal
npm run dev

This starts a local server. Open http://localhost:4321 in your browser. The site reloads automatically every time you save a file — no need to restart.

Useful Commands

CommandWhat it does
npm run devStart local development server at localhost:4321
npm run buildBuild the production-ready static site into dist/
npm run previewPreview the production build locally before deploying

Tip: Always run npm run preview after a build to check everything looks correct before uploading to the server.

Project Structure

The project follows the standard Astro layout. Here are the folders and files you will interact with most often:

src/ content/ ← All editable content lives here news/ ← News articles (one .md file per article) cars/ ← Car data files (one .md file per car) pages/ ← One .astro file = one page of the site index.astro ← Home page about.astro ← About Us page team.astro ← Meet the Team page sponsors.astro ← Sponsors page competitions.astro ← Competitions page contact.astro ← Contact page join-us.astro ← Join Us / Apply page car/ current.astro ← Current car specs page archive.astro ← Past cars archive news/ index.astro ← News listing page [slug].astro ← Individual news article page components/ ← Reusable UI pieces (header, footer, etc.) layouts/ Layout.astro ← Main site shell (banner, nav, footer) styles/ global.css ← Global CSS variables and base styles public/ ← Static files served as-is (images, logos)

Rule of thumb: For day-to-day content updates (news, cars, team) you only ever touch files inside src/content/ and public/. You rarely need to edit src/pages/ unless you are changing the layout of a specific page.

The Content System

The site uses Astro Content Collections — a simple, structured way to manage content using Markdown files. Each collection is a folder inside src/content/. Each item in a collection is one .md file with a frontmatter block (the section between --- dashes) and a body of text below.

news/
Each file is one article. The filename becomes the URL slug. Files are automatically sorted by date.
cars/
Each file is one car generation. Used to populate the archive page and individual car detail pages.

Managing News03
Chapter 03
Managing News Articles

Adding a New Article

  1. Create a new file in src/content/news/. Name it in lowercase with hyphens, e.g. fs-balkans-2025-results.md. The filename becomes the URL: /news/fs-balkans-2025-results.

  2. Add the frontmatter block at the top of the file (see template below).

  3. Write the article body in Markdown below the second ---.

  4. Save — the article appears automatically on the news listing and homepage.

Article Template

src/content/news/your-article-slug.md
--- title: "Your Article Title Here" date: 2025-07-15 # YYYY-MM-DD format category: competition # competition | team | technical | event author: "Your Name" coverImage: "/news/your-image.jpg" # place image in public/news/ excerpt: "One sentence summary shown on the news card." featured: false # true = shown as hero on news page --- Your article content goes here. You can use **bold**, *italic*, ## Headings, and - bullet lists.

Frontmatter Fields Reference

FieldRequiredDescription
titleYesArticle headline shown on cards and the article page
dateYesPublication date — articles are sorted newest first
categoryYescompetition, team, technical, or event
authorNoAuthor name shown on the article
coverImageNoPath to image — place in public/news/
excerptYesShort summary for news cards and SEO description
featuredNoSet to true to feature as the hero article

Editing an Article

Open the relevant .md file in src/content/news/ and edit the frontmatter or body text. Save — changes appear instantly in dev mode.

Deleting an Article

Delete the .md file. The article and its URL are automatically removed on the next build.

Note: Only one article should have featured: true at a time. If multiple are featured, the most recent one is used as the hero.

Managing Cars

Updating Current Car Specs

The current car specs page (/car/current) is edited directly in src/pages/car/current.astro. Open the file and update the specs object at the top — it is a plain JavaScript object with tab names as keys.

Adding a New Car to the Archive

  1. Create a new file in src/content/cars/, e.g. tsr5.md.

  2. Fill in the frontmatter using the template below.

  3. Add the car's cover image to public/ and reference it in coverImage.

Car File Template

src/content/cars/tsr5.md
--- title: "TSR 5" year: 2026 years: "2025–2026" tagline: "Your one-line description" coverImage: "/tsr5.jpg" engine: "Engine name and displacement" weight: "XXX kg" powertrain: engine: "Engine model" displacement: "XXX cm³" ecu: "ECU model" drivetrain: "Drivetrain description" chassis: type: "Frame type" dimensions: length: "XXXX mm" width: "XXXX mm" height: "XXXX mm" wheelbase: "XXXX mm" seasons: - "FS Event Name Year" results: - event: "FS Event Name Year" placement: 1 year: 2026 --- Optional longer description of the car here.

Archive page: The car archive at /car/archive automatically lists all files in src/content/cars/, sorted by year (newest first). No extra step needed.

Chapter 05
Team & Sponsors

Updating the Team Roster

The team page is managed directly in src/pages/team.astro. Open the file and find the members array near the top. Each member is an object — add, edit or remove entries as needed.

src/pages/team.astro — members array
{ name: "First Last", role: "Chief Engineer", department: "Mechanical", // Mechanical | Electronics | Aero | Business image: "/team/firstname-lastname.jpg", linkedin: "https://linkedin.com/in/...", // optional },

Place member photos in public/team/. Use consistent dimensions — ideally square or 3:4 portrait, minimum 400×400px.

No photo yet? Leave the image field as an empty string "" — the page will show a placeholder automatically.

Adding Sponsor Logos

Sponsor logos appear in the animated marquee on the homepage and on the Sponsors page. Two sets of logos are used — white (for dark backgrounds) and colour (for light backgrounds). They are stored in:

public/ Logo sponsori alb/SVG/ ← White/light version logos Logo sponsori albastre/SVG/ ← Colour version logos

  1. Add the SVG logo files to both folders (white version and colour version).

  2. Open src/pages/index.astro and find the marqueeLogos array.

  3. Add an entry with the exact filenames:

src/pages/index.astro — marqueeLogos array
{ name: 'Sponsor Name', fileW: 'Logo-white.svg', fileB: 'Logo-blue.svg' },

The sponsor also needs to be added to src/pages/sponsors.astro where the full sponsor grid is defined. Find the sponsors array in that file and add an entry with name, logo, url, and tier fields.

Updating Social Links

Social links (Instagram, Facebook, LinkedIn) are set in two places:

  • src/components/layout/Footer.astro — the footer social icons
  • src/pages/contact.astro — the contact page social links

Search for the existing URLs and replace them with updated ones.

Site Configuration06
Chapter 06
Site Configuration

The Launch Event Banner

The amber banner at the top of every page is configured in src/layouts/Layout.astro. Find the element with id="launch-banner" and update:

What to changeWhere to find it
Event name / textThe <span> inside the banner div — change the text directly
YouTube Live URLThe href="#" on id="banner-stream-link" — replace # with the YouTube URL
Hide the bannerAdd style="display:none;" to the id="launch-banner" div
Dismiss reset (testing)In browser DevTools → Application → Local Storage → delete banner-tsr4evo-dismissed

Upcoming Events (Homepage)

The event countdown on the homepage is driven by the events array in src/pages/index.astro:

src/pages/index.astro
const events = [ { title: 'Formula Student Balkans', date: new Date('2026-07-12'), end: new Date('2026-07-17'), location: 'Dej, Romania' }, // add more events here ];

Navigation Links

The nav links are defined in src/components/layout/Header.astro in the navLinks array at the very top. Add, remove or reorder items there.

Hero Stats (Homepage)

The four animated stat counters on the homepage are the stats array in src/pages/index.astro. Each has a value, num (the number to count to), title and desc.

About Page — Milestones

The timeline on the About page is the milestones array at the top of src/pages/about.astro. Add a new object for each milestone with year, title and desc.

Favicon

The favicon is public/logo.png. Replace this file with a new one (keep the same filename and use a square PNG, minimum 512×512px).

Page titles & SEO descriptions are set in each page's <Layout title="..." description="..."> tag at the top of every .astro file.

Images & Media

Where to Place Files

All public assets (images, audio, PDFs) go inside the public/ folder. Files placed here are served exactly as-is — a file at public/hero-image.jpg is accessible at /hero-image.jpg in the site.

public/ hero-image.jpg ← Homepage hero background logo.png ← Site logo + favicon team-section.jpg ← About page team photo tsr4hybrid.jpg ← Current car hero image engine.mp3 ← Engine sound for Wake the Beast button team/ ← Team member photos news/ ← News article cover images Logo sponsori alb/SVG/ ← White sponsor logos Logo sponsori albastre/SVG/ ← Colour sponsor logos

Image Guidelines

UseFormatRecommended size
Hero / car backgroundsJPG1920×1080px minimum, compressed to under 500KB
News cover imagesJPG1280×720px (16:9)
Team member photosJPG / PNG400×400px square or 400×533px (3:4)
Sponsor logosSVGVector — any size, keep viewBox clean
FaviconPNG512×512px square

Compressing Images

Large images slow the site down. Before adding a photo, compress it using one of these free tools:

  • squoosh.app — drag and drop, choose WebP or JPG, adjust quality
  • tinypng.com — simple drag and drop PNG/JPG compression

Aim for under 300KB for hero images and under 100KB for cards and thumbnails.

Replacing the Hero Image

The homepage hero is public/hero-image.jpg. To replace it, simply save a new file with the exact same name — it overwrites the old one. No code change needed.

Replacing the Engine Sound

The "Wake the Beast" audio clip is public/engine.mp3. Replace the file with a new MP3 of the same name. Keep it under 2MB for fast loading.

Naming convention: Use lowercase letters and hyphens only — no spaces or special characters in filenames. Example: tsr5-launch-event.jpg ✓   TSR5 Launch Event.jpg ✗

Building & Deploying

Building for Production

When your changes are ready, build the static site. This generates a dist/ folder containing plain HTML, CSS and JS files — everything the server needs.

Terminal
npm run build

After the build finishes, preview it locally to check everything is correct:

Terminal
npm run preview

Uploading to the UPT Server

The site is hosted at formulastudent.upt.ro on a university server. Upload the contents of the dist/ folder to the server's web root using SFTP or the file manager provided by the IT department. The specific credentials and path will be provided by your UPT system administrator.

Important: Upload the contents of dist/, not the folder itself. The server should serve index.html from the web root.

Git Workflow

All changes are tracked with Git. Follow this workflow to keep the history clean:

Terminal — standard workflow
# 1. Check what changed git status # 2. Stage your changes git add src/content/news/my-new-article.md # 3. Commit with a clear message git commit -m "Add FS Balkans 2025 results article" # 4. Push to GitHub git push

Commit Message Guidelines

TypeExample message
New articleAdd FS Balkans 2025 results article
Update contentUpdate TSR4 specs — correct weight to 256kg
New team memberAdd Mihai Ionescu to electronics roster
Fix a bugFix mobile menu overlapping About link
Add sponsorAdd Continental to sponsor marquee

Good habit: Commit often and with specific messages. It makes it easy for future team members to understand what changed and when.

Troubleshooting10
Chapter 10
Troubleshooting
ProblemLikely causeFix
npm run dev fails Dependencies not installed or wrong Node version Run npm install first. Check node -v ≥ 18.
My new article doesn't appear Missing required frontmatter field or wrong date format Check title, date, category and excerpt are all present. Date must be YYYY-MM-DD.
Image not showing Wrong path or file not in public/ Confirm file exists in public/. Path in code must start with / (e.g. /news/photo.jpg).
Banner still shows after dismiss localStorage has the dismiss flag set DevTools → Application → Local Storage → delete banner-tsr4evo-dismissed.
Dark mode not toggling JavaScript error or localStorage stuck Open DevTools console for errors. Clear localStorage and reload.
Build fails with content error Frontmatter field type mismatch Check the terminal output — it will name the file and field. Common issue: date must be a plain date, not a string in quotes.
Fonts look wrong after deploy Google Fonts blocked by browser or network The fonts load from Google CDN. If the server blocks external requests, download and self-host the font files.
Page shows old content after deploy Browser cache Hard refresh: Cmd+Shift+R (Mac) / Ctrl+Shift+R (Windows).
Mobile horizontal scroll An element is wider than the viewport DevTools → toggle device toolbar → inspect which element overflows. Likely a long unbreakable string or image without max-width.

Getting Help

  • Astro docs: docs.astro.build — comprehensive reference for all Astro features
  • Tailwind docs: tailwindcss.com/docs — utility class reference
  • Git history: Run git log --oneline to see all past changes and identify when something broke
  • Revert a file: git checkout -- src/pages/index.astro to undo uncommitted changes to a file

When in doubt, don't delete — comment out. Wrap the section in <!-- ... --> (HTML) or {/* ... */} (Astro/JSX) so you can restore it easily.
